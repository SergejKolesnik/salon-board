# Salon Board

Розклад косметологічного кабінету та безпечний журнал підтверджених вимірювань складу тіла — веб-застосунок на FastAPI.

## Вимірювання Withings

Після входу адміністратора відкрийте `/body` або кнопку **Вимірювання** у панелі адміністратора.

1. Оберіть наявного клієнта та відкрийте коротку сесію на салонній станції.
2. Новий вимір потрапляє у чергу та не додається до клієнта автоматично.
3. Працівник перевіряє відповідність клієнта і підтверджує запис.

Є два окремі безпечні сценарії Withings:

1. **Салонна станція.** Працівник відкриває сесію для конкретного клієнта, отримує останній вимір зі спільних ваг та підтверджує його. Ваги ніколи самі не визначають людину.
2. **Особисті ваги клієнта.** Клієнт авторизує свій Withings у вікні Withings. Після синхронізації вимір теж потрапляє в чергу, а не одразу в медичну/клієнтську картку.

OAuth-код, Client Secret, refresh token та access token не потрапляють у браузер. Сервер зберігає токени лише у зашифрованому вигляді. Для активації додайте у змінні середовища хостингу значення з `.env.example`: `WITHINGS_CLIENT_ID`, `WITHINGS_CLIENT_SECRET`, `WITHINGS_REDIRECT_URI`, `WITHINGS_TOKEN_ENCRYPTION_KEY`. Останній — окремий ключ Fernet, наприклад згенерований командою `Fernet.generate_key()` у захищеному середовищі; не комітьте його.

Перед запуском потрібно задати `TURSO_URL` і `TURSO_TOKEN` у змінних середовища. Орієнтир — `.env.example`; фактичні секрети ніколи не комітяться.

## Можливості

- **Сітка майстрів** — всі спеціалісти бачать навантаження один одного в реальному часі
- **Рецепція** може створювати, редагувати та видаляти записи
- **Перевірка конфліктів** — система не дозволить записати двох клієнтів на той самий час до одного майстра
- **Мобільний вигляд** — вкладки по майстрах, адаптований під телефон
- **Клік на слот** — форма одразу з заповненими часом і майстром
- **CRM клієнтів** — пошук і вибір клієнта, імпорт із контактів Android, єдиний формат українських телефонів і захист від дублів за номером
- **Turso** — хмарна база даних, параметри підключення задаються тільки через середовище

## Технології

- **Backend:** Python 3.10+, FastAPI, Turso
- **Frontend:** Vanilla JS, HTML/CSS — вбудований в `main.py`, без збірки
- **Одна залежність:** `fastapi` + `uvicorn`

## Запуск

```bash
# 1. Клонувати
git clone https://github.com/YOUR_USERNAME/cosmo-schedule.git
cd cosmo-schedule

# 2. Встановити залежності
pip install -r requirements.txt

# 3. Додати TURSO_URL та TURSO_TOKEN у середовище, потім запустити
uvicorn main:app --reload

# 4. Відкрити у браузері
# http://localhost:8000
```

Схема бази створюється автоматично під час запуску. Фактичні секрети не зберігаються у репозиторії.

### Робоча локальна модель без секретів

Щоб перевірити повний інтерфейс до налаштування Turso чи Withings, задайте `SALON_BOARD_DEMO=1` і запустіть застосунок. Він створить локальний файл `salon-board-demo.db`; не вмикайте цей режим на хостингу. Увійдіть як адміністратор паролем `admin123`, відкрийте **Вимірювання**, створіть клієнта, відкрийте коротку сесію та натисніть **Тестово отримати вимір**. Так можна побачити всю чергу й підтвердження без жодних акаунтів або реальних даних.

## API

| Метод | Endpoint | Опис |
|-------|----------|------|
| GET | `/api/masters` | Список майстрів |
| POST | `/api/masters` | Додати майстра |
| GET | `/api/appointments?date=YYYY-MM-DD` | Записи на дату |
| POST | `/api/appointments` | Створити запис |
| PUT | `/api/appointments/{id}` | Оновити запис |
| DELETE | `/api/appointments/{id}` | Видалити запис |
| POST | `/api/clients` | Створити клієнта CRM |
| GET | `/api/breaks?date=YYYY-MM-DD` | Перерви на дату |
